# 组织与呈现原则

## 先回答读者的问题

一份易读报告先回答三件事：

- 结论是什么；
- 这对我有什么影响；
- 下一步由谁做什么。

核心结论先给总判断，再按内容模块逐项列一句话摘要，可用短要点或紧凑表格；进度任务再列观察状态清单，不把多件事揉成一段。使用 verdict.topics 复用正文 summary，避免摘要独立漂移。历史通过、待实施、待验收和未知不能混作完成；必要限制可在清单内说清，避免再加一段同义提醒。

随后只保留影响决定或执行的主题。主标题用最短内容名，如“增量、接法、工时、验收”；具体问题写较弱的副标题，如“推荐怎么接？”。按内容、功能或阶段选分类，取决于读者如何作决定，这些例子不是固定目录。

技术简报和交接通常有 3–6 个正文主题。内容更多时先合并重复论点，再把完整源码、历史版本和逐项记录放到描述性链接或就近详情。拆成十几章、给每项事实一张卡片或把同一结论重复到多个表格，都会增加理解负担。

## 默认阅读顺序

1. **核心结论**：固定为第一个内容块，短结论、必要图解、下一步；关键限制直接写明，可简述阅读逻辑。
2. **各主题主区**：先用一句话回答该主题的问题，再解释理由、变化、影响或做法。读者只看这一层也能理解本节结论及会改变判断的限制。
3. **就近详情**：让需要动手或审阅的读者继续查完整步骤、例子、版本和恢复信息。展开后应多回答一个具体问题；只有同义复述便删掉，无第二层就不折叠。
4. **来源与附录**：由一句可核查的断言跳到对应材料，保留定位和证明范围。跨主题背景和长原文集中存放，不替代本节必要说明。

默认左栏放报告主题名、短目录和少量可常看的全局重点；点击切换主区。主区不再多占一行重复报告名，主标题下常显低强调副标题，对应目录项旁保留同文提示，主标题不带问号控件。导航高度用于高价值投入、边界、决策或下一步，不为填满而堆摘要，常规单屏放下。低相关“资料／补充材料”统一归附录。窄屏紧凑顶部导航；continuous 才保留旧章节浮层，无脚本和打印完整保留内容。

## 说人话

- 一句话写清主语、动作和结果。例如“宿主继续加载普通 JAR，不新增独立服务”，比“维持现状架构形态”更清楚。
- 先用已有业务叫法或常用词；陌生名称能换成自然话就换。只有会影响理解且必须保留的术语、缩写或别名才用下划线解释，释义说清在本报告里指什么。含义无法确认时如实写未知。
- 先写业务含义，再写类名、接口、版本和路径。技术原文放在同句后半段或就近详情。
- 一段只讲一个判断；并列事项用项目符号，执行顺序用编号。
- 字段名、内部枚举和自定义代号留在确实需要复用的作者资料或就近技术详情；面向读者写实际状态，如“目标环境还没验收”。精简用语不抹掉历史、待核验、建议和未知的区别。
- 不把“已检查 18 项”“包含 12 个章节”当成成果；只有能帮助决定的数值才进指标卡。
- 不用“完善、优化、赋能、闭环”等词代替具体动作和可观察结果。

## 图、表和交互

- 图只在关系或顺序比文字更容易理解时使用。边要说明谁调用谁、通过什么方式、结果去哪里。
- 变化图先统一要比较的问题和口径，按相同角色对照入口、关键路径与结果；流程结束后的查阅、告警或核验不能替代结果。先对材料比逻辑，再看成品的各视图。详见[图解模型](diagram-model.md)。
- 表只比较相同维度；单元格出现长论证时改成正文或列表。
- 搜索、状态筛选和详情抽屉适合多问题审计。普通简报用图解、短对照和必要就近详情；删无价值段落，不用更多卡片和折叠包装冗长。
- 术语下划线只用于目标读者可能不懂、且理解错误会影响判断的词。触屏和打印仍要有完整释义。
- 图片支持放大、再次点击关闭、遮罩关闭、按钮关闭和 Esc 关闭；关闭后回到原图。

颜色只做辅助。状态按关注程度配色：灰色为历史参考或普通说明，蓝色为需推进，橙色为待核验／未知，红色为阻塞／风险，绿色为当前范围内明确完成。历史结果不显示为当前完成，状态文字和证据限制始终保留，不因颜色自行推断业务优先级。正文重点可以少量使用加粗、浅色底和等宽原文；整段染色、满屏卡片和装饰性指标会分散注意力。打印时即使没有颜色，结论、限制和状态仍须看懂。

## 证据放在哪里

断言用右上数字角标，悬停或聚焦简述，点击到本节来源；来源区只列编号与描述性入口，不再复述气泡。完整出处、定位、限制和逐项记录统一在附录维护一份。必要验收边界仍常显，不能借精简来源删掉证明能力的限制。

证据需要说明来源、定位、日期或版本以及能证明什么。源码、运行、业务和发布证据仍需分开判断，但无需机械地在每份简报中生成四个空框。历史记录和计划不能写成当前已验收。

## 阅读验收

技术检查完成后，再做一次独立阅读复核。审阅者只看首屏和主题标题，应能直接复述：

1. 推荐或判断是什么；
2. 为什么对读者有影响；
3. 下一步先做什么；
4. 最大限制是什么；
5. 需要时去哪里看完整依据。

再打开一个主题，说出比首屏多知道了什么，沿一条断言走到具体出处，说清证据能和不能证明什么。可用独立 Agent 前向验证并如实标明身份，不能冒充真人试读。复述失败时先删重复、改标题、补主语和动作，不靠更多说明卡补救。

浏览器检查桌面导航单屏、主区切换／返回／深链接、390 px、无脚本和完整打印；实际使用三态图、角标、术语、图片时验证对应交互，截图需要目检。零报错、DOM数量和零溢出只证明结构或交互，不能证明读懂。
